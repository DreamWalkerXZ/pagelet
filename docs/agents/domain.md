# Domain Docs

This repository uses a single domain context.

## Before exploring

Read `GLOSSARY.md` at the repository root and relevant decisions in `docs/adr/`.
If they do not exist, proceed silently.

Create glossary entries when terms are resolved and ADRs when consequential
trade-offs are settled. Create files only when there is content to record.

## Vocabulary

Use the glossary's canonical terms in code, issues, specs, and discussions.
Flag conflicting terminology and unresolved domain concepts.

Keep implementation details out of the glossary.

## Decisions

Read relevant ADRs before proposing changes.
Explicitly flag any proposal that contradicts an existing ADR.
