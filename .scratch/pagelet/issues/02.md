Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Administrators provision ordinary users or additional administrators and find users through a paginated management API.

Delivery phase: 1 — API, raw access, OpenAPI, and CLI.

## Acceptance criteria

- [ ] Only administrators can create and list users; unauthenticated and ordinary users cannot enumerate accounts.
- [ ] Enforce unique immutable usernames: 3–32 lowercase ASCII letters, digits, or single hyphens, with no leading or trailing hyphen.
- [ ] Accept account passwords of 12–128 Unicode characters, including spaces, without trimming or normalization; store irreversible verifiers.
- [ ] Fix the administrator or ordinary-user role at creation; expose no registration or role-change operation.
- [ ] Issue exactly one full-permission API token on creation and disclose it only in that response, never in later account reads.
- [ ] Support username search and page-number pagination defaulting to 20 and capped at 100; document and integration-test permissions and validation.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
