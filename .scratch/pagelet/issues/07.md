## Parent

Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Administrators reassign pages and remove accounts only when doing so preserves content ownership and an administrator.

Delivery phase: 1 — API, raw access, OpenAPI, and CLI.

## Acceptance criteria

- [ ] Only administrators transfer page ownership; require the last-read page version, advance it, and preserve slug, content and access password.
- [ ] Immediately remove previous owner privileges and revoke all page access grants; independent administrator authority and ordinary visitor access still apply.
- [ ] Only administrators delete users, and only users owning zero pages can be deleted; reject deletion of the final administrator.
- [ ] Delete account credentials/sessions and immediately revoke API access when the user is removed; provide no suspension or role-change operation.
- [ ] Ensure concurrent administrator deletion cannot remove the final administrator, and concurrent page creation/transfer and user deletion cannot leave orphan pages.
- [ ] Verify the complete transfer-then-delete lifecycle, authority matrix and races through HTTP integration tests with real SQLite; extend OpenAPI.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
