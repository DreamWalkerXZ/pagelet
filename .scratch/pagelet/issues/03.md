## What to build

An authenticated user publishes a page, visitors read it through its slug or raw endpoint, and authorized users find their pages.

Delivery phase: 1 — API, raw access, OpenAPI, and CLI.

## Acceptance criteria

- [ ] Publish immediately, including empty Markdown, with stable page ID, version, owner, and creation/update timestamps; provide no separate title or draft state.
- [ ] Accept custom slugs of 1–64 lowercase ASCII letters, digits, or single hyphens with no leading/trailing hyphen; reject invalid or occupied values without rewriting.
- [ ] Generate 12-character lowercase ASCII alphanumeric slugs and retry collisions without overwriting another page.
- [ ] Accept valid UTF-8 Markdown up to 1 MiB in UTF-8 bytes, with a bounded request limit accommodating JSON encoding overhead.
- [ ] Provide API source/metadata reads and raw Markdown at /_/raw/<slug>, with content responses disallowing caching and no HTML rendering endpoint.
- [ ] Owners list only their own pages; administrators list all and filter by owner. Support slug search and pagination default 20/max 100, ordered by descending update time with stable ID tie-breaking.
- [ ] Test publication, reads, discovery permissions, boundaries, collision handling, and restart persistence through HTTP with real SQLite; extend OpenAPI.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
