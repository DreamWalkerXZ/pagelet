Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Users log in to create, edit and delete pages through the API, with preview matching the public reader.

Delivery phase: 2 — browser interface and embedded release.

## Acceptance criteria

- [ ] Serve login and editing under /_/app/* using HttpOnly sessions and CSRF protection, never browser-stored account API tokens.
- [ ] Create pages with generated or custom slugs and optional access passwords; edit content, slug and password, and delete with clear permanent-deletion feedback.
- [ ] Reuse public-reader rendering for live Markdown preview and preserve entered work when API validation or version conflicts prevent saving.
- [ ] Send last-read versions for mutations and clearly report 409 conflicts without silently overwriting server content.
- [ ] Use only the established API for account/page behavior; unauthorized and expired sessions show appropriate recovery/login flows.
- [ ] Verify login, publication, preview, password changes, slug changes, conflict handling and deletion with real-browser tests; embed all required frontend assets.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
