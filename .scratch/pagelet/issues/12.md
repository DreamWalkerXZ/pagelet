## Parent

Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Users find their pages and manage their password or single API token through the web interface.

Delivery phase: 2 — browser interface and embedded release.

## Acceptance criteria

- [ ] Provide owner-scoped page listing, slug search and pagination, ordered consistently with the API, with links to reading and editing.
- [ ] Provide password change, API token reset and logout through existing endpoints, without introducing token collections or device management.
- [ ] Display newly issued tokens once, without adding later retrieval or persisting tokens in browser storage.
- [ ] After password changes, reflect global session revocation and offer reauthentication; token-only reset preserves the current web session.
- [ ] Test list isolation, pagination/search, secret display, credential transitions and logout through a real browser; assets remain embedded.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
