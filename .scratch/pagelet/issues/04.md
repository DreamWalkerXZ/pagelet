## Parent

Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Owners and administrators safely change page content or address and permanently delete pages without overwriting concurrent work.

Delivery phase: 1 — API, raw access, OpenAPI, and CLI.

## Acceptance criteria

- [ ] Address management operations by immutable page ID and require the last-read version for edits and deletion; return 409 for stale versions.
- [ ] Owners and administrators may mutate pages; other ordinary users and visitors may not.
- [ ] Advance the version on successful changes, update timestamps consistently, and reject invalid changes without partial writes.
- [ ] Slug changes preserve page identity, owner, content, and access policy, release the old slug immediately, and create no redirect or reservation.
- [ ] Deletion permanently removes page application records and releases its slug; do not add a recycle bin or secure-erasure promise.
- [ ] Test competing updates/deletions, stable identity, uniqueness, old-link behavior and slug reuse via HTTP and real SQLite; extend OpenAPI.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
