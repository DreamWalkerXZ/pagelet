Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Visitors open a page by slug and read safely rendered Markdown, unlocking protected pages and accessing raw content when authorized.

Delivery phase: 2 — browser interface and embedded release.

## Acceptance criteria

- [ ] Serve /<slug> and embedded assets under /_/assets/* from the executable, fetching source through the API rather than backend HTML rendering.
- [ ] Render standard Markdown plus GFM tables, display-only task lists, strikethrough and autolinks; code blocks need no syntax highlighting.
- [ ] Disable embedded HTML, filter dangerous URL schemes and sanitize output; permit external images through Markdown syntax without file uploads.
- [ ] Support password prompts, page-scoped HttpOnly grants, raw links, missing pages and expired/revoked access without leaking protected metadata.
- [ ] Provide a shared rendering path suitable for editor preview; no math, Mermaid, footnotes, social previews or no-JavaScript reading.
- [ ] Use real-browser tests for GFM fixtures, malicious HTML/URLs, public/protected reading, raw access and self-contained asset delivery.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
