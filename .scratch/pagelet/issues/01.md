## What to build

Run a self-contained Rust service initialized locally, then authenticate to its API with the first administrator's token.

Delivery phase: 1 — API, raw access, OpenAPI, and CLI.

## Acceptance criteria

- [ ] Build a Rust executable using local SQLite and a configurable persistent data directory; provide interactive initialization with hidden password input and one-time token display.
- [ ] Refuse to serve before initialization; provide no default credentials or public initialization endpoint, and prevent reinitialization from replacing existing data.
- [ ] Default to HTTP on 127.0.0.1:8080 with CLI/environment overrides; apply forward migrations and reject newer database schemas.
- [ ] Provide authenticated current-account inspection using a bearer token; reject invalid credentials and do not expose stored secrets.
- [ ] Verify initialization, restart persistence, configuration, schema compatibility, and authentication through executable CLI smoke tests and HTTP integration tests with real temporary SQLite.
- [ ] Expose the initial public OpenAPI contract and extend it with every subsequent API slice.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
