## Parent

Part of https://github.com/DreamWalkerXZ/pagelet/issues/1.

## What to build

Administrators manage all instance pages, transfer ownership and provision or delete users through the same API.

Delivery phase: 2 — browser interface and embedded release.

## Acceptance criteria

- [ ] Provide all-page listing, slug search, pagination and owner filtering with administrator reading/editing/deletion powers, including protected pages.
- [ ] Provide version-aware administrator-only ownership transfer and show conflict/authorization errors without implementing owner-initiated transfer.
- [ ] Provide user creation with fixed role, username search, pagination, password/token reset and one-time new-token display.
- [ ] Permit deletion only for users with no pages; explain rejection of the final administrator and support the transfer-then-delete workflow.
- [ ] Expose no role-change or account-suspension control; ordinary users cannot access administrator functions even through direct API calls.
- [ ] Verify administrator workflows, fixed-role permissions, token handling, deletion constraints and transfer revocation with real-browser tests.

## Testing approach

Test observable behavior, using the HTTP boundary with real temporary SQLite as the primary seam, executable CLI smoke tests where applicable, and browser tests for web behavior. Keep authorization and persistence real rather than mocking business rules. Update the public OpenAPI contract alongside every affected API operation. Follow the parent specification and accepted domain decisions; do not add deferred features.
